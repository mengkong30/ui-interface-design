# 参考整合与批量迭代

## 从参考到修改

用户连续上传参考时，把观察落实到布局、图形和层级，不只反复评价“高级”。明确参考用于哪一部分：数据页的数字与图表比例、菜单节奏、App 标志构图、操作页或页面关系；保留此前确认的颜色与交互约束。只有收到修改指令才执行相应设计变更。

整理素材时保留原文件与来源标识，按用途分类，并记录“采用 / 不采用”的具体特征。素材缩略图不代替原文件；参考中的商标、图形路径不直接成为用户产品的原创资产。网页已打开不等于工具已成功读取；读取超时不能说成用户没有打开页面，也不能声称看过未取得的图像。

## App 图标与应用内图形

区分三个层级：
- App 入口图标：有完整底形、配色和专属构图；设计重点是轮廓、负空间、叠放关系与辨识度。给通用符号加彩色方块不自动等于完成了 App 图标设计。
- 二级列表功能图标：表达功能，视觉重量较轻，通常无 App 外壳。不要将应用入口 Logo 批量铺进设置、健康或运动列表。
- 页面状态图形：围绕状态设计，如呼吸节奏、手机响铃。可以较大，但不必沿用 App 底板；有动画时图形服务状态。

具体是否带底板以用户确认的设计系统为准。先完成代表性图标并在九宫格中检查，再扩展。复杂的负空间、交叠或抽象运动符号若不易识别，先修轮廓，不靠更多渐变补救。

本案例的选择是：App Logo 仅用于应用总入口；应用内、二级栏使用无底板功能图形。鲜亮蓝色为主，红绿点缀。此配色与无标签九宫格不是所有产品的默认规则。

## 居中必须有参照物

先确认坐标系与所属容器，再计算位置：
- 状态页图形、圆环、状态文字可共用屏幕中心线；作为一组，在标题和底部操作之间安排空间。
- 按钮文字居中于各自按钮；双按钮的两段文字绝不能都移到屏幕中心。
- 列表图标和文字相对于当前行对齐，图表标签相对于对应列或绘图区对齐。

禁止仅凭 `textAlignHorizontal == CENTER` 将所有文本设置为 `(screenWidth - textWidth) / 2`。该属性不表达元素属于屏幕、按钮还是卡片。局部坐标与绝对坐标也不能混算。

优先让按钮背景和标签归属同一容器，或使用明确的组件关系。不得只靠显示文字匹配归属；重复标签、隐藏备份和不同状态都会产生误配。批量修正前列出作用范围与归属，先检查一个单按钮和一个双按钮案例。

## 批量改版与回归

修改前记录页面功能、关键读数、控件和状态；减少文字与卡片不意味着删除必要功能，例如音乐音量、睡眠图例、目标单位和暂停/结束操作。

一轮局部修改后检查受影响的关系：
- 对齐：标签中心对按钮中心、图形中心对所属容器中心，核对文字边界和相邻控件间隔。
- 图形：实际尺寸辨识度、圆角、细桥接处和孔洞；再放大看路径尖刺、重叠和裁切。
- 数据：圆环进度来源、睡眠阶段时长和比例、图例与颜色一致性。示例趋势需如实标为设计示例，不捏造测量数据。
- 同步：主组件、当前页面、源页面以及请求范围内的关联展示；历史区排除在更新之外。

按实际修改风险检查代表状态，再扩大到同类；不要把检查到的按钮数说成页面数。记录修改数与检查范围，导出新图验证，旧预览不作为新版本交付证据。

## 当前版与历史版

用户要求保留旧版时，先建立独立历史区，再修改当前版。当前页面区与当前组件区只有一个明确的有效版本；源页面、复制页面和展示实例应有可追踪映射。

历史快照不能继续引用会被修改的主组件，否则更新会污染旧稿。能保留独立可编辑副本时优先保留；若工具限制导致使用 SVG 快照，说明文字可能已转轮廓、组件链接和原型行为不再保留，不称其为完整可编辑工程备份。

不要通过整页替换无意删除原型连接、实例覆盖、自动布局或变量绑定。需要替换时先盘点这些属性，保留或明确披露限制。不要把网页、Figma 静态稿、原型和作品集都称作“已同步”，只报告实际更新的交付面。

## 数据页构图：把图表作为主体

依据读数任务选择构图，不把所有页面统一成“大数字 + 小图标 + 底部按钮”：

| 任务 | 可采用的图形 | 必须保留的信息 |
|---|---|---|
| 目标完成度 | 圆环或进度条，核心值放在环内或邻近处 | 指标、目标、完成量；超过目标时如实表达 |
| 随时间变化 | 宽折线、柱状图、阶段时间轴 | 时间范围、单位，必要的刻度和图例 |
| 当前状态或阈值 | 仪表弧、当前点、阈值线 | 阈值来源与当前值；不要凭视觉设计生成健康判断 |
| 倒计时 | 中央大数字配剩余进度弧 | 剩余时间、设定时长、暂停与结束状态 |
| 运动中 | 大时长，距离和心率紧凑成组 | 每个读数的单位、必要操作 |
| 呼吸过程 | 扩散、收缩的柔和形状 | 当前阶段、剩余时间、停止入口 |

数字、图形和留白共同组成主视觉。图表可直接放在背景上；卡片只在需要分组、承载操作或提高背景对比时使用。次要指标用小图标、数字与贴近的单位组成紧凑组；删除重复说明之前先确认读数仍有含义。

普通心率趋势不能画成心电图式尖峰，除非界面确实展示对应的心电数据。装饰性周期波形不能冒充真实心率趋势；弧长、柱高、时间轴长度应与所表达的数据一致。尚无数据的概念稿使用明确标识的示例。只有经过验证的数据来源才能支持健康区间或好坏判断。

## 色彩层次与当前值强调

背景、图表轨道、有效数据和当前点形成明暗层次。可在图表附近使用同色系的轻渐变，或用端点、光点强调当前位置；强调必须对应实际状态。避免所有线条、数字与按钮同时高亮。

用户要求鲜亮时，检查渐变的暗端是否让整个图标显脏；优先用亮度接近的同色系端点、白色或浅色主体建立层次。大面积辉光、玻璃按钮、强模糊仅在读数与操作仍清晰时采用，不作为“设计感”的固定配方。

统一功能语义比照搬参考颜色更重要。不要因为参考是橙色、紫色或青色就重置已确认色板。黑底与局部彩色渐变可以共存；是否采用由当前风格决定。App 图标与应用内图形的分层规则仍然适用。

## 表盘探索与设备适配

图形化表盘可组合数字字形、圆形信息块、进度弧或刻度，但时间仍应一眼可读，辅助信息不能争夺第一层级。点阵、叠排等特殊数字需完成字形集合和变化状态，再检查窄字、宽字及不同时间组合。

圆形屏幕参考只能提供构图方法，迁移到圆角方屏时重新分配空间与安全边距；不要机械套圆，也不复制其顶部按钮或导航方式。沿用已确认的手势与标题规则。

## 页面关系图的语义

可采用“入口在左、模块横向展开”的布局：表盘 → 应用菜单 → 模块入口 → 详情或操作状态。一个模块占一行或一个明确分区，界面预览为主体，连线保持克制。

箭头只表示可发生的跳转或操作顺序。晴天与夜晚、不同表盘等视觉变体用并列状态表达，不能为了排成一行而串成操作链。暂停、恢复、结束用真正的分支；共用页面标明复用。图例说明手势、状态切换和一般页面跳转的差异。图片中的小字读不清时，只提取可观察到的结构，不推断隐藏功能。

## 内容型页面与缺失状态

音乐封面、联系人头像、天气场景等真实内容可以成为主视觉。选择与当前内容相关的素材，并准备无图片、加载失败等占位状态；不要用随机人物或不相关封面冒充实际内容。

列表按信息类型组织：歌曲用封面、歌名和演出者，联系人用头像与姓名，健康指标用数值、单位及必要趋势。统一对齐、间距与触控区域，不必强求所有列表的内部构成完全相同。长标题需明确换行、截断或聚焦后滚动规则，并用长内容验证，不能将截图中的意外裁切照搬进产品。

## 进度图形、详情与反馈

同一信息族统一线宽、端点圆角、底轨亮度与数字—单位间距。亮色表示有效进度，底轨保留总量；横条便于比较多个对象，圆环适合一个主要比例。连续进度可以使用渐变，离散阶段则需要可区分的颜色和图例，不能用一条连续渐变替代分类。

进度环中央可放播放/暂停等相关操作，但需验证图形与操作的分工：环表示进度，按钮有独立且足够的触控区域，读数仍清晰。若没有拖动调节能力，不设计会让人误认为可拖动的手柄。

总览负责多指标比较，详情聚焦一个指标和其目标或趋势。阶段反馈如“完成一半”可以采用短暂提示；设计时说明触发条件、停留或关闭方式、返回位置，并确保运动计时和主要操作不被无故打断。只在用户授权的功能范围内增加状态，不因参考出现就新增功能。

低电量等明确提醒可提高局部或全页色彩强度，但同时保留文字或符号，不能仅靠颜色表达。强色提醒应有明确进入与退出条件，不把警示风格扩散到所有日常页面。

重复上传同一参考时检查内容是否真的变化；相同参考合并索引，仅补充新的观察，不重复归档和重复累积规则。

以上参考分析属于可试用的设计方法；不能把它描述成已经在项目中实现或经设备测试验证的结论。
